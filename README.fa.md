# پنل SSH VPN

این پروژه برای ساخت حساب‌های تونل SSH و SOCKS روی Ubuntu 24.04 است. مدیریت کاربران از طریق وب انجام می‌شود. چون مخزن گیت‌هاب خصوصی است، برای دریافت آن روی هر سرور باید به همان سرور دسترسی خواندن مخزن بدهید.

## اجزا

- **Django:** ورود مدیر، ساخت و حذف کاربر VPN، فعال و غیرفعال‌سازی، تغییر رمز و ثبت سابقهٔ عملیات.
- **PostgreSQL:** نگهداری اطلاعات حساب‌ها؛ رمز VPN در پایگاه‌داده ذخیره نمی‌شود.
- **ابزار `sshvpnctl`:** عملیات محدود روی حساب‌های گروه `sshvpn` با دسترسی ریشه.
- **OpenSSH جداگانه:** اتصال VPN روی پورت ۲۲۲۲؛ سرویس SSH مدیریتی، ورود این گروه را رد می‌کند. شِل، اجرای دستور و SFTP در سرویس VPN بسته‌اند.
- **nftables:** جلوگیری از اتصال تونل کاربران به آدرس‌های خود سرور و شبکه‌های خصوصی. روی سرورهایی که IP عمومی با NAT به سرور می‌رسد، مسیر برگشت به IP عمومی را جداگانه آزمایش کنید.
- **Nginx و Gunicorn:** ارائهٔ پنل وب؛ دستور `menu` برای مدیریت سرویس‌ها، پشتیبان‌گیری، باز و بسته‌کردن پورت VPN و گرفتن SSL در آینده.

## نتیجهٔ آزمون نسخهٔ پیشین روی VPS

نسخهٔ پیشین روی Ubuntu 24.04 نصب شد. اتصال واقعی با رمز عبور از طریق SOCKS به اینترنت برقرار شد؛ اتصال به SSH داخلی سرور و اجرای فرمان مسدود شد. عملیات ساخت، غیرفعال‌سازی، فعال‌سازی، تغییر رمز و حذف کاربر نیز با پایگاه‌داده و حساب لینوکسی آزمایش شد. تغییرهای نصب HTTP و ساخت مدیر در ابتدای نصب هنوز روی VPS اجرا نشده‌اند.

پنل فعلاً **بدون SSL و فقط روی `127.0.0.1:8080`** باز است. پورت VPN پس از آزمون جداسازی شبکه می‌تواند با `sudo menu vpn-public` عمومی شود. این کار وب پنل را عمومی نمی‌کند.

## نصب روی سرور دیگر: ابتدا HTTP

پس از گرفتن snapshot و باز نگه‌داشتن اتصال مدیریتی SSH، مخزن خصوصی را با کلیدی که به آن دسترسی خواندن دارد دریافت کنید:

```bash
git clone git@github.com:EmadNajafi/sshpanel.git
cd sshpanel
sudo bash deploy/install.sh
```

**اولین پرسش‌های نصب‌کننده** نام کاربری و رمز مدیر پنل هستند؛ رمز دوباره پرسیده می‌شود و هنگام تایپ نمایش داده نمی‌شود. سپس دامنه یا IPv4 پنل را وارد می‌کنید. پنل روی **HTTP پورت ۸۰** بالا می‌آید و SSL خودکار گرفته نمی‌شود. اگر IP را از قبل می‌دانید، می‌توانید آن را به دستور بدهید: `sudo bash deploy/install.sh 203.0.113.10`.

کاربر VPN از طریق SSH فقط به سرویس تونل روی پورت ۲۲۲۲ احراز هویت می‌شود؛ شِل، اجرای فرمان و SFTP ندارد و سرویس SSH مدیریتی پورت ۲۲ ورود او را رد می‌کند. این محدودیت در VPS آزمایشی با حساب واقعی بررسی شد. روی هر سرور جدید نیز پیش از بازکردن عمومی پورت ۲۲۲۲، `sudo menu vpn-public`، مقصدهای داخلی و اتصال مدیریتی را آزمایش کنید.

برای آزمایش محلی وب بدون بازکردن پورت ۸۰:

```bash
sudo bash deploy/install.sh --local-test
```

در این حالت نیز مدیر در ابتدای نصب ساخته می‌شود. روی رایانهٔ خودتان تونل مدیریتی بسازید:

```bash
ssh -N -L 127.0.0.1:8080:127.0.0.1:8080 root@SERVER_IP
```

سپس `http://localhost:8080/login/` را باز کنید. برای دیدن گزینه‌های سرور `sudo menu` را اجرا کنید. وقتی خودتان SSL خواستید، دامنه را به IP سرور وصل کنید، پورت‌های ۸۰ و ۴۴۳ را باز کنید و `sudo menu ssl panel.example.com admin@example.com` را اجرا کنید. اگر دریافت گواهی شکست بخورد، تنظیمات HTTP قبلی برمی‌گردد. تا قبل از SSL، رمز مدیر روی HTTP عمومی رمزگذاری نمی‌شود؛ از شبکهٔ مطمئن یا تونل SSH استفاده کنید.

سرویس VPN در نصب اولیه فقط روی `127.0.0.1:2222` گوش می‌دهد. پس از آزمایش اتصال عمومی و مسدودبودن مقصدهای داخلی، `sudo menu vpn-public` را اجرا کنید. برای برگرداندن آن به حالت محلی `sudo menu vpn-local` را بزنید. نصب‌کننده پورت SSH مدیریتی و دیوار آتش سرور را تغییر نمی‌دهد.
